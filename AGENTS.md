# Working in HTML-Pet

This repository is the independent browser slime-pet experiment. Use [README.md](README.md) for its scope and entry points if you have not already read it. Native PC-Pet and LFS companion work are separate projects unless the owner explicitly authorizes shared behavior or assets.

## At task start

1. Confirm the requested outcome, applicable instructions and permitted paths. Inspect existing source and instructions before changing them.
2. If you have access, open [Project Office Start Here](https://github.com/SyrisBruhh42/Project-Office/blob/main/hub/START-HERE.md), choose route `html-pet`, and recover mission `MISSION-HTML-PET`. Check current coordination and ownership before a source mutation; a historical author or checkpoint is not a live claim.
3. Keep the source task bounded. Office coordinates projects; source-local instructions and the authorized task govern this repository. A link, plan or prior CI result does not grant additional product or runtime authority.
4. Record the source commit, inspected paths, actual checks, result and remaining uncertainty in the task handoff. Distinguish source observations from executed behavior and completed work from pending decisions.

Office is an optional private coordination resource. If access is unavailable, use this repository’s applicable instructions and the existing task authorization, and state the missing context. Keep private Office records and conversations out of public files, issues and pull requests. Do not make access to Office a requirement for using the prototype.

## Progression and saved-state boundaries

Preserve the pending owner decision on reward and real-time/offline balance before expanding these systems. Do not invent a cap, reward formula or accepted save behavior from historical notes. Continue independent authorized documentation or investigation while the decision remains pending.

For changes that affect these areas, establish evidence for the agreed reward sequence, restart persistence, visible invalid-save recovery and the agreed offline rule. Source inspection, a page loading successfully, or passing unrelated checks does not establish those outcomes.
